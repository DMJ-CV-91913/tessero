# NumPy / SciPy gap analysis (0.2.0 beta, 2026-09)

This page interprets the [coverage inventory](numpy-scipy-coverage.md): what
Tessero can replace today, where it is weaker, and what is worth closing
next. The inventory is generated from the code's public API
(`tools/api-dump.php` → `tools/gap_inventory.py`), so the counts below cannot
claim a function that does not exist. The work items that follow from it are
in the [open issues](open-issues.md) list.

## Summary

The measured figures are on the [coverage page](numpy-scipy-coverage.md), and all of them are generated.
The curated rows (M1) are checked against the public API. The symbol coverage (M2 to M5) counts every public
NumPy/SciPy symbol, and a symbol counts only when its NumPy/SciPy fixture passed on that backend in the
recorded run. This page interprets them without restating them.

- **scipy.special and scipy.stats are the SciPy modules furthest along, and are identical on both backends.**
  Every real-valued `scipy.special` ufunc runs SciPy's own code (xsf, Boost.Math and SciPy's glue, vendored).
  The `scipy.stats` distributions follow SciPy's `rv_continuous`/`rv_discrete` machinery method by method,
  and the descriptive statistics, correlation and hypothesis-test functions are ported too. What remains is
  listed under [Per area](#per-area).
- **The NumPy statistics core is done.** That covers median, quantile/percentile (all 13 methods), the
  nan-reductions, histogram/bincount/digitize, cov/corrcoef, unique and set operations, partition, lexsort
  and searchsorted. Every `Generator` distribution method draws bit-identical streams, on both backends.
- **The largest NumPy gaps are array manipulation and construction helpers.** These are `split`/`stack`
  variants, `tile`/`repeat`, `flip`/`roll`, `pad`, `*_like`, `meshgrid`, `diag`/`tri*`, `kron`/`outer`,
  polynomials and `interp`, plus the smaller dtypes.
- **SciPy beyond special and stats is thin.** `optimize`, `sparse` and `linalg` cover the original
  workloads. `interpolate`, `signal`, `integrate`, `spatial`, `ndimage`, `cluster` and `constants` are not
  started.
- **The extension matches FFI on everything built on the function registry.** It still lacks the older
  FFI-only modules: `Linalg`, the full `Fft`, sparse matrices, `optimize`, `.npz`, and some `NDArray` methods.

## Per area

"Evidence" is how correctness is established. *Fixtures* are values generated by NumPy/SciPy in the pinned
reference environment ([ADR 0012](../architecture/adr/0012-pinned-reference-environment.md)) and compared
on both backends. *Bit-identical* means the same bytes or iterates as NumPy/SciPy. Performance figures are
1M float64 elements on the review host (AVX-512, one thread) against NumPy 2.x.

## Where Tessero matches or goes beyond NumPy/SciPy

- **Reproducibility.** `Generator` streams are bit-identical to
  `numpy.random.default_rng(seed)`. A simulation seeded in PHP and in Python
  produces the same numbers.
- **File interchange.** `.npy` files are byte-identical in both directions, and
  memory maps open NumPy-written files zero-copy.
- **Solver behaviour.** `brentq` returns the same bits as SciPy, and BFGS and
  Nelder-Mead follow the same iterates. Results can be checked against Python
  line by line.
- **Operations features NumPy does not have.** A per-process native memory
  budget that throws before allocating, allocation and mapping counters for
  monitoring, per-request settings reset under Octane and queues, a
  `bin/tessero doctor` check, and Laravel casts, validation and a facade.
- **Markov decision processes** in C with OpenMP (value, policy and modified
  policy iteration, finite horizon). This is not in NumPy/SciPy;
  pymdptoolbox is the Python equivalent.

## Extension vs FFI: what the extension still lacks

The extension exists for speed and zero FFI overhead. It currently lacks:

- **NDArray methods:** `empty`, `view`, `expandDims`/`squeeze`,
  `swapAxes`/`moveAxis`, `broadcastTo`, `concatenate`/`stack`,
  `take`/`put` beyond row lists, `filter`/`setWhere` as methods, `diff`,
  `round`, `isclose`/`allclose`, `flatten`, `flatNonzero`, and `contiguous`.
- **Sorting:** sort/argsort along an axis. The extension flattens.
- **Modules:** `Linalg` (via LAPACKE), the full `Fft` (rfft, fft2, frequency
  helpers), a stateful `Generator`, sparse matrices, `optimize` (minimize,
  roots, least squares), and `.npz`.
- **Error types.** A few invalid-argument paths raise different exception
  classes on the two backends. For example, `argmax` with a list of axes is
  a `ShapeException` on the extension and a `TypeError` on FFI.

Everything the kernel already provides (ufunc loops, reductions, sort, FFT,
mmap, `.npy`) is shared C code (ADR 0010). Closing the extension gap is
mostly binding work, not new numerics. The estimate is 4–6 sessions for
everything above except sparse and optimize.

## Recommended priorities

Ranked by how many PHP workloads each item unblocks per session of work.
Each links to its issue in the [open issues](open-issues.md).

Done since the last revision: the array construction and manipulation helpers (split/stack families,
tile/repeat, flip/roll, pad, `*_like`, meshgrid, diag/tri, kron/outer, the in-place writers) and the numeric
routines (`interp`, the `poly*` functions, windows, `gradient`, `trapezoid`) go through the function registry,
so both backends have them, verified by NumPy fixtures (PAR-2.3, ADR 0013).

1. **The rest of scipy.special:** the non-ufunc functions, and complex-valued ufuncs, which need complex
   support in the function registry (TSR-116).
2. **Extension parity for linalg, FFT and the remaining NDArray methods,** so the extension can be the only
   package installed (TSR-102 to TSR-107).
3. **The rest of scipy.stats:** multivariate distributions, resampling methods and `gaussian_kde` (TSR-304).
4. **scipy.interpolate** 1-D splines (TSR-305), and `polyfit`/`roots` (TSR-306).
5. **Large-scale solvers:** HiGHS and `spsolve` (TSR-110, TSR-111).
6. **Performance:** vectorised trig, SIMD sort, faster complex FFT (TSR-201 to TSR-203).
7. **Data interchange:** CSV, then Arrow/Parquet (TSR-307).

## Out of scope

- String, object, structured and record dtypes.
- `numpy.ma` masked arrays (nan-reductions and boolean masks cover the common
  uses).
- GPU support.
- A scikit-learn clone (Tessero should serve as a backend for Rubix ML
  instead).
- Model training.
- `scipy.io` formats other than `.npy`/`.npz`.

These are not counted as gaps for 1.0.

## Caveats

- **Verified on one platform.** All test, fuzz, soak and benchmark evidence
  comes from one Linux x86-64 host with PHP 8.4. CI has never run. Windows,
  macOS, arm64 and musl have not been compiled, and PHP 8.1–8.3 have not been
  tested. Until the P0 items in the [open issues](open-issues.md) are
  closed, the ● marks mean "implemented and tested on Linux x86-64".
- **Benchmarks are single-host.** They were run with AVX-512 available. On
  AVX2-only CPUs, NumPy's sort advantage shrinks and the exp/log gap changes.
  Treat the ratios as indicative.
- **The curated inventory counts rows, not symbols.** One row may group several functions, and "partly
  supported" rows (◐) count as supported there. The symbol coverage (M2) on the same page counts symbols.
