# 0002. NumPy and SciPy are the specification

- Status: Accepted
- Date: 2026-09-26

## Context

Numerical libraries fail quietly: a wrong promotion rule, an off-by-one in a
slice or a biased random stream produces plausible numbers. PHP developers
who adopt Tessero are often porting models from Python, and need identical
results to trust the port.

## Decision

Semantics are taken from NumPy 2 and SciPy: broadcasting, NEP 50 type
promotion, slicing, integer wrap-around, NaN handling, random streams, solver
conventions (bounds, marginals, status codes). Tests compare against fixtures
generated by running NumPy/SciPy (`tests/fixtures/generate_parity.py`), not
against hand-written expectations. A CI job regenerates the fixtures with the
latest NumPy/SciPy releases.

## Consequences

- "Correct" is testable and unambiguous.
- Random numbers are bit-identical to NumPy's default generator, so Monte
  Carlo work is reproducible across languages.
- Where exact equality is impossible (LAPACK builds, FFT algorithms) the
  tolerance is written down per area ([Testing](../testing-and-quality.md)).
- Deviations must be deliberate and documented (e.g. `exponential()` is not
  stream-identical; the extension's `==` compares bytes).
- NumPy behaviour changes surface as CI failures and must be triaged.
