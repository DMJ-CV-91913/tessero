# Releasing

## Versioning

Semantic Versioning. `libtessero` (`tsr_version()`), the FFI package
(`Tessero::VERSION`), the extension (`PHP_TESSERO_VERSION`), and the
`tessero/laravel` constraint move together and always carry the same version.

## Checklist

1. **Changelog**: move "Unreleased" entries under the new version and date.
   Breaking changes go under their own heading, and each is listed in
   `docs/operations/upgrading.md`.
2. **Version bump** in `csrc/src/alloc.c` (`tsr_version`), `src/Tessero.php`
   (`VERSION`), `ext/php_tessero.h` (`PHP_TESSERO_VERSION`) and
   `laravel/composer.json` (`tessero/tessero` constraint).
3. **Sync and regenerate**:
   ```bash
   bash tools/sync-ext.sh
   php -d ffi.enable=1 -d extension=ext/modules/tessero.so tools/gen-api-docs.php
   python tests/fixtures/generate_parity.py     # only if NumPy/SciPy were updated
   python tests/fixtures/generate_ufunc.py
   python tests/fixtures/generate_npy.py
   ```
4. **Full verification**: all CI jobs green on the release commit (native ×6,
   PHP matrix, sanitizers, fuzz, extension + ASan, Laravel app, preload, docs,
   Docker, benchmarks) and the last nightly run green (30-minute fuzzing per
   target, 5.5-hour soaks, property tests ×50).
   **Long soak**: `tools/soak.php` for at least 24 hours per backend on
   production-like hardware (see `docs/operations/soak-testing.md`);
   attach the JSON summaries to the release.
5. **Tag** `vX.Y.Z` (signed). The `release` CI job packages the binaries with
   `LICENSE`, `THIRD_PARTY_NOTICES.md` and every third-party licence text
   (`lib/licenses/`), and attaches to the GitHub release:
   - `tessero-binaries.tgz` (reproducible tar: sorted, fixed owner, mtime =
     the tagged commit's date);
   - `tessero.cdx.json`, a CycloneDX 1.5 SBOM generated by `tools/sbom.py` from
     the tables in `THIRD_PARTY_NOTICES.md` and `composer.json` (vendored C/C++
     code has no manifest a scanner could find, so keep those tables exact);
   - `SHA256SUMS` and `SHA256SUMS.sigstore.json`, a Sigstore keyless signature
     made by the release workflow's identity;
   - SLSA build provenance and an SBOM attestation for `tessero-binaries.tgz`,
     stored by GitHub (`actions/attest-build-provenance`, `actions/attest-sbom`).

   Before announcing, verify what was published:
   ```bash
   gh release download vX.Y.Z -R DMJ-CV-91913/tessero
   sha256sum -c --ignore-missing SHA256SUMS
   cosign verify-blob --bundle SHA256SUMS.sigstore.json      --certificate-identity "https://github.com/DMJ-CV-91913/tessero/.github/workflows/ci.yml@refs/tags/vX.Y.Z"      --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
   gh attestation verify tessero-binaries.tgz -R DMJ-CV-91913/tessero
   gh attestation verify tessero-binaries.tgz -R DMJ-CV-91913/tessero      --predicate-type https://cyclonedx.org/bom
   ```
6. **Publish**: Packagist picks up the tag for `tessero/tessero`. The
   `laravel/` and `ext/` directories are published as read-only subtree splits
   (`tessero/laravel`, `tessero/tessero-ext`) tagged with the same version. `ext/`
   is self-contained (it carries its own `libtessero/` copy), so PIE can build
   the split directly.
7. **Docs**: the docs job deploys the site for the tag.
8. **Announce** with a summary, upgrade notes and checksums.

## Vendored components: quarterly re-sync

Once a quarter (and whenever an advisory names one of them), the owner of
`THIRD_PARTY_NOTICES.md` goes through this list and records the outcome in the
changelog:

1. **Inventory.** For each row of the vendored table in `THIRD_PARTY_NOTICES.md`
   (SciPy 1.17.1 glue, QUADPACK, `brentq` and FITPACK; xsf commit 0d0a593;
   Boost.Math commit 5e088ff; NumPy 2.4.4 random distributions; netlib f2c;
   Joe & Kuo Sobol' table; MT19937 via NumPy), compare the pinned version with
   the latest upstream release.
2. **Advisories.** Query OSV for each upstream
   (`https://osv.dev` for PyPI `scipy` / `numpy`, GitHub `boostorg/math`,
   `scipy/xsf`) and GitHub security advisories; also check the runtime
   libraries in the "linked at build or run time" table (OpenBLAS, LAPACK,
   GCC runtime) for the distributions the binaries target. Dependabot covers
   the GitHub Actions, Composer, pip and Docker manifests, not these.
3. **Re-sync** when there is a fix that applies, or at least once a year:
   update the copy under `csrc/third_party/`, re-apply the local changes listed
   under "Local modifications" (every one is marked `Tessero` in the source),
   run `bash tools/sync-ext.sh`, regenerate fixtures only through
   `tools/parity/gen-fixtures.sh` if the reference NumPy/SciPy moved, and run the
   full verification (step 4 of the checklist).
4. **Record** the new version, commit or date in `THIRD_PARTY_NOTICES.md`, so
   the next SBOM is right.

## Hotfixes

Branch from the tag (`release/X.Y`), fix with a test, bump the patch version,
and follow the checklist. Forward-port to `main`.

## Yanking

If a release ships a correctness or security defect, publish a patch release
first, then mark the bad version as yanked on the GitHub release and in the
changelog, with the reason.
