# Tessero: notes for Claude Code

## Parity program (active)

Mission and rules: `prompts/numpy-scipy-parity-program.md`. The short form:

- Covered means verified: a generated SciPy/NumPy fixture passes on **both** backends. Never loosen a tolerance,
  skip a test or edit generated files to get green; exclusions only by category E1-E7 in `tools/parity/scope.yaml`.
- Coverage numbers are generated (`tools/parity/report.py`); never typed into docs by hand.
- Ledger: `.work/ledger.md` (status per item). Decisions: `.work/decisions.md`. After a restart: read this file,
  the ledger, then continue with the first WIP/TODO item. Update the ledger after every item.
- New numerical functions go into the kernel function registry (`csrc/src/fn_core.c` + module tables, ADR 0011).
  Both bindings read it at runtime (`Tessero\Native\Registry` for FFI, `ext/tessero_fn.c` for the extension); the
  FFI façades (`src/Special.php`, `src/Np.php`, ...) are generated by `tools/parity/gen-facades.php` after a build.

Per item: spec entry (`spec/*.yaml`, element-wise) or table entry (`csrc/src/np_*.c`, `csrc/cxx/*.cpp`) ->
fixtures (`bash tools/parity/gen-fixtures.sh <group>`: the generators refuse to run outside the pinned
environment, ADR 0012) -> implementation -> build -> façades -> `run-tests.php --backend=ffi` and
`--backend=ext` -> docs -> ledger. Deviations from SciPy's plain output only through the generator rules in
`docs/project/reference-deviations.md` (guards, undef rows, U1/U2, data-derived per-call tolerances).

Gate: `tools/parity/gate.sh` (QUICK=1 skips sanitizers, fuzzing, soak and benchmarks).
Records after a run: `php tools/parity/record-suites.php <junit.xml>...`, `python3 tools/parity/report.py --record
"<phase>"`, `php tools/api-dump.php > tools/parity/api.json`, `python3 tools/gap_inventory.py tools/parity/api.json >
docs/project/numpy-scipy-coverage.md`.

## Build notes

- `/mnt/user-data/outputs` is mounted noexec here: build binaries with `BUILD=<scratch dir>`.
- `ext/libtessero` is a synced copy of `csrc`: run `bash tools/sync-ext.sh` after kernel changes.
- Files on `/mnt/user-data/outputs` get timestamps that lag the clock (about 30 min), and `touch` does not
  fix it: make then sees stale objects as up to date. Delete the objects (`rm -rf $BUILD/c $BUILD/cxx`) before a
  build that must include recent edits; the extension is safe when built from a fresh copy (`cp -r ext`).
- Extension build: copy `ext/` to a scratch dir, `phpize && ./configure --enable-tessero && make`.
- No composer vendor dir here (offline): PHPUnit suites run through a scratch shim that writes JUnit XML
  (`JUNIT=<file>`), which `record-suites.php` reads.
- `RecursiveDirectoryIterator` lists nothing on this FUSE mount; tools walk directories with `scandir`.
