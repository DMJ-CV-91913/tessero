# Decisions (one line each)

- 2026-09-28 The kernel registry (C table) is the single source of truth for callable functions; both bindings interpret it at runtime (the extension registers classes and arginfo from it at MINIT, as Tessera\Ext\Math already does for ufuncs). spec/*.yaml carries only verification metadata (reference, domain, tolerance). Replaces "codegen of bindings" in the prompt: less generated code, same guarantee (ADR 0011).
- 2026-09-28 FFI facade classes (Special, Stats, ...) are generated from the registry by tools/parity/gen-facades.php so that reflection and IDEs see real methods; a freshness check runs in the gate.
- 2026-09-28 Fixtures are JSON (floats as shortest round-trip repr, nan/inf as strings), one file per module; exact enough and loadable by both backends without .npz support.
- 2026-09-28 Order changed: special -> numpy stats -> scipy.stats before the extension's legacy gaps (TSR-102..107), because stats is the user's priority; legacy gaps are Phase 4.
- 2026-09-28 The workspace is not a git repository; the ledger records completed items instead of commit hashes.
- 2026-09-28 0-d results are returned as PHP floats (as NDArray::sum() already does); multi-output functions return an associative array keyed by SciPy's result field names.
- 2026-09-28 Special functions come from the libraries SciPy 1.17.1 itself calls: xsf (pinned commit 0d0a593), Boost.Math (pinned 5e088ff, only the 178 headers used) and SciPy's glue (Boost wrappers, cdflib, Cython ports, xsf_wrappers), vendored in csrc/third_party with licences. Results are therefore SciPy's by construction; the fixtures verify it. Cost: libtessera now needs a C++17 compiler (static libstdc++ in the FFI binary; PHP_REQUIRE_CXX in the extension). My earlier hand-written sf_*.c were deleted.
- 2026-09-28 The PHP class for the registry dispatcher is Tessera\Native\Registry ("Fn" collides with PHP's fn keyword).
- 2026-09-28 Method names are camelCase (PSR-1; log_ndtr -> logNdtr); every façade also has apply('log_ndtr', ...) and FUNCTIONS for the SciPy names.
- 2026-09-28 Inputs on which SciPy itself crashes or hangs (found by tools/parity/crash_scan.py) get a `guard:` in the spec: Tessera returns NaN there instead of taking the PHP process down. Documented as a deliberate deviation.
- 2026-09-28 Where SciPy's vendored code itself never terminates (cdflib cumtnc: nctdtridf, nctdtrinc), the vendored copy stops the sum only when it provably cannot end (the tail is bounded by 2(|d|+|e|)/(1-lambda/i) and the partial sum lies below minus that bound), with a 1e9 backstop; a thread-local flag makes the rest of that evaluation return at once and the wrapper returns NaN. (First version: a 1e6-term cap; too low for 2 convergent rows, and a 1e8 cap cost 12 s per hang row.) Marked `capped:` in the spec and listed in THIRD_PARTY_NOTICES.md.
- 2026-09-28 numpy functions that are not reductions keep NumPy's signature: digitize/isin/searchsorted take no axis/keepdims (axis "hidden"); cumulative functions and partitions take an int axis only and no keepdims (AX_SINGLE, AX_NOKEEP) and place their 1-D core in the axis's position (CORE_INPLACE, CORE_FLAT for axis=None). Integer inputs give int64 results where NumPy keeps the integer dtype (CORE_INTLIKE); values are computed in float64, so integer sums/products are exact only below 2^53 (NumPy wraps modulo 2^64): recorded as an open issue.
- 2026-09-28 numpy call fixtures (fixtures_np.py) replay recorded calls with keyword arguments as PHP named arguments and compare result kind (int/float/bool), shape and values; NumPy exceptions must be exceptions in Tessera. unique_values is compared as a set (NumPy 2.3+ leaves its order unspecified).
- 2026-09-28 NDArray::array() (both backends) accepts lists of arrays, as numpy.array([a, b]) does.
- 2026-09-28 Fixtures are generated in a pinned numerical environment (ADR 0012): NumPy's AVX-512 float64 dispatch is disabled, so its transcendental loops equal glibc's (0 differences in 20 000 inputs per function, except tanh, which uses NumPy's own AVX2 kernel); the generators refuse to write otherwise. Consequence: Math::cbrt returns glibc's value (the Newton correction matched AVX-512 NumPy only); tolerances that absorbed the machine difference were removed.
- 2026-09-28 Upstream-bug rules in the stats fixture generator: U1 (invalid shape parameters -> nan where SciPy's private method raises on the empty valid set), U2 (vectorised result != element-by-element result -> element-by-element). SciPy's actual output stays in the fixture under "upstream"; report.py counts them (docs/project/_generated/deviations.md).
- 2026-09-28 Tolerances may be derived per call from the call's data with a stated bound (epps_singleton_2samp: rtol = max(1e-12, cond(C) eps), the pseudo-inverse perturbation bound); the runner honours a case's `tol`.
- 2026-09-28 A fixture for a function Tessera does not implement is reported as `missing` (not implemented), not as a failure: the runner's exit status reflects wrong results only, and report.py counts missing functions as not implemented.
- 2026-09-28 Rows whose SciPy value depends on evaluation history (uninitialised work arrays in xsf's spheroidal code) are detected by re-evaluating reference_ub functions in a fresh interpreter in reverse order, and recorded as undef.
- 2026-09-28 levy_stable: SciPy's public pdf/cdf/rvs (not logpdf, sf, ...) shift loc by 2 beta scale log(scale)/pi for alpha == 1; the framework has a narrow hook (Cont::public_loc_shift) applied only to those methods; extra fixture sets (EXTRA in fixtures_stats.py) exercise alpha == 1.
- 2026-09-28 The special fixture generator keeps integer columns as JSON integers, so the runner exercises the integer loops SciPy used (they had silently fallen back to the float loops).
- 2026-09-28 No C++ exception may reach C or PHP: fn_core.c calls every gufunc core and routine through cxx/fn_guard.cpp (bad_alloc/length_error -> MemoryError, others -> ValueError with the message); dist_method/dist_rvs_array catch; callbacks invoked by vendored C (QUADPACK, brentq) park exceptions and rethrow after the C routine returns.
- 2026-09-28 Where SciPy's own code crashes (segfault, stack overflow) Tessera returns NaN, fixed as narrowly as possible: argument guards only where SciPy is NaN just inside the guard (Mathieu), otherwise a local modification on exactly the non-terminating path (xsf hyp2f1, Boost 1F1). Where SciPy raises (RecursionError, OverflowError, MemoryError), Tessera raises.
- 2026-09-28 Allocations sized by a parameter go through tsd::alloc_count: over the kernel budget, or physical RAM when no budget is set, is MemoryError before allocating (under overcommit_memory=1 a huge request would otherwise succeed and the worker be OOM-killed).
- 2026-09-28 Integer inputs of int-like numpy functions compute in int64 with NumPy's wrap-around (CORE_INT64 engine mode), not in float64.
- 2026-09-28 Build hygiene: /mnt timestamps lag; builds that must include recent edits delete the object directories first.
- 2026-09-28 NumPy's array construction and manipulation functions are registry routines (ADR 0013): sequence (`name[]`), variadic (`*name`) and in-place (`&name`) arguments, sequence results; they return copies where NumPy returns views (the NDArray methods keep views).
- 2026-09-28 Argument provenance decides NumPy's conversions: a PHP int is exact (`ival`), a PHP list follows Python-sequence rules (int() of float indices, bincount of float lists, int()/range checks when writing into integer arrays), an NDArray follows ndarray rules (safe casting, TypeError for float indices).
- 2026-09-28 Integer results are exact: 0-d int results carry `ival`; unique and the set operations on int64 run on ranks in a sorted key table; the fixture runner compares integers exactly instead of as floats.
- 2026-09-28 Kernel error codes select the PHP exception class in both bindings (EINDEX -> IndexError, ETYPE -> DTypeError, ESHAPE -> ShapeError, ENOMEM -> MemoryError, else ValueError); parameter conversions of a float where NumPy wants an int are ETYPE (NumPy's TypeError).
- 2026-09-28 Where NumPy itself is undefined (bincount of 2^63-1, offset -2^31, int64 casts of |k| >= 2^63) Tessera raises or returns the defined result and documents it; where NumPy's integer arithmetic overflows inside an interpolation (quantile of wide int32 samples) Tessera computes in float64 and documents it.
- 2026-09-28 Usage-weighted coverage is reported beside symbol coverage, never instead of it. Weights are call sites that resolve statically to census symbols in the non-test library code of widely used packages at pinned tags (tools/parity/usage.py); array method calls are not attributable and are not counted; calls to excluded symbols are shown separately and left out of the in-scope figure. The most-called gaps set the order of extension-parity work.
- 2026-09-30 Next-work order: extension parity for the most-called functions (numpy.linalg, empty, round, allclose, isclose, ...) moves ahead of PAR-1.2, because the usage-weighted report shows they carry the largest share of unverified real-world calls on the extension.
- 2026-09-30 numpy.asfortranarray returns a C-contiguous copy: Tessera has no Fortran memory order (ADR 0005: byte strides but arrays are materialised C-contiguous). asfortranarray therefore returns the same contiguous copy as ascontiguousarray; the result's values, shape and dtype match NumPy exactly, and Tessera does not expose the .flags['F_CONTIGUOUS'] distinction, so no observable Tessera behaviour differs. The parity fixtures compare values/shape/dtype (not memory order), so both pass. result_type/promote_types/finfo/iinfo/einsum are deferred within PAR-4.1: result_type/promote_types return a numpy.dtype and finfo/iinfo return objects, which the registry result model (tsr_result kinds none/float/int/bool/array/sequence - no string/object) and the fixture encoder (np.asarray of a dtype/finfo object) do not represent; they need a string result kind in tsr_result + both bindings + a bespoke fixture path, tracked as a follow-up. einsum needs a subscripts parser and general tensor contraction (its own item).
- 2026-09-30 PAR-4.1 sequencing: within "extension parity for the most-called functions", implement the pure-array `np` core functions (round, isclose, allclose, ascontiguousarray/asfortranarray, result_type/promote_types, finfo/iinfo) before numpy.linalg, even though linalg carries more usage weight. Reason: the core functions reuse existing machinery (the `np` namespace already maps to the Np class in both bindings, the runner's `np` module, fixtures_np.py) and touch no build system, so they bank verified coverage with zero risk to the green baseline; linalg needs LAPACKE linkage in three build files, a new `linalg` namespace->class path in both bindings, and new runner/census/fixtures wiring, which is designed and built as its own step. Verifiability and keeping the baseline green (program section 1) outrank the usage-weight ordering for intra-item sequencing.
- 2026-09-30 Factor decompositions (svd, eigh, qr) are verified after sign canonicalisation: their factors are unique only up to the sign of each singular/eigen vector (and, for degenerate spectra, rotation within a subspace), which differs between LAPACK builds. Both the reference (tools/parity/fixtures_linalg.py: eigh_canon/svd_canon/qr_canon) and the kernel (csrc/src/np_linalg.c: sign_canon, and a non-negative R diagonal for qr) apply the same rule - flip each vector so its largest-magnitude entry is >= 0 (numpy/scikit-learn svd_flip); qr flips so R's diagonal is >= 0 - so exact comparison is valid. Fixtures use non-degenerate inputs (distinct, separated singular/eigen values) and, for full_matrices svd, square matrices only (the null-space columns of a non-square full U are an arbitrary orthonormal basis and are not comparable; non-square svd is fixtured with full_matrices=False). Singular values are transpose-invariant, so values-only paths (svdvals/matrix_rank/cond/norm) run dgesdd 'N' in col-major on A^T. eig/eigvals stay FFI-only until the complex128 result path exists (PAR-1.3).
- 2026-09-30 numpy.linalg-through-the-kernel design (PAR-4.1b): new C module csrc/src/np_linalg.c registers routines under a `linalg.` namespace; each wraps row-major LAPACKE (LAPACK_ROW_MAJOR) on a private contiguous float64 copy from fn_arg_doubles, reading shape/ndim from args[i].arr, and loops over leading dims for stacked (...,M,M) inputs exactly as src/Linalg/Linalg.php does (dgesv/dgetrf/dgetri/dpotrf for solve/inv/det/cholesky; dgesdd/dgelsd for svd/pinv/matrix_rank/lstsq/norm ord2). LAPACKE is linked via csrc/Makefile LDLIBS (-llapacke -lopenblas), ext/config.m4 (PHP_ADD_LIBRARY lapacke) and ext/config.w32. Both bindings gain a `linalg.` prefix -> Tessera\Linalg / Tessera\Ext\Linalg class in the MINIT/registry loop (ext/tessera_fn.c, src/Native/Registry.php); tools/parity/run-tests.php gains a `linalg` module entry; census/scope classify the numpy.linalg symbols; a new tools/parity/fixtures_linalg.py records the calls. Singular/not-PD raise: the fixture runner accepts any Throwable where numpy raises (run-tests.php:322), so the generic kernel error path (ValueError) passes the fixture; a dedicated LinAlgError class is a later refinement.
- 2026-09-30 Reference host for this program run: the reference host (tessera-ref), Ubuntu 24.04.4 glibc x86-64, driven over SSH. CPU is Haswell (i7-4790, no AVX-512), so NumPy's AVX-512 float64 dispatch (the reason for the ADR 0012 pin) is a no-op and float64 transcendentals already equal glibc's; `OPENBLAS_CORETYPE=SkylakeX` from gen-fixtures.sh only affects BLAS-order fixtures (linalg/matmul), which cannot be regenerated bit-identically here — the committed AVX-512-host fixtures remain authoritative for those and already pass on this box. Pinned Python is 3.12 (venv `.venv-parity`) rather than the reference's 3.11; NumPy 2.4.4 / SciPy 1.17.1 are exact per requirements.txt and their numerics are independent of the CPython minor, so non-BLAS fixture generation stays verifiable.
